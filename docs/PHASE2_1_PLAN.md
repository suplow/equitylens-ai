# Phase 2.1 — Financial integrity implementation plan

Financial baseline: 87eb4fdd88945a9edb8b6c5ff97dd6a50fd34bf5. Working branch: feature/equitylens-financial-validation, based on orchestrator report commit 355357b. Existing application checks: lint/typecheck/build, 49 unit and 16 E2E passed before financial changes.

## Verified issues, not assumed reviewer claims

1. `openingReport().find()` selects the first same-date/scope/basis balance report. Valid annual and Q4 inputs can yield different ROE/FCFF when reordered. Block ambiguity or require an explicit, validated opening report selection. Regression: integrity.test.ts.
2. DCF discounts to fiscal year end but reports upside/MOS against a later market date without rolling forward. Relative valuation shares the comparison problem. Preserve dated valuation and lock incompatible comparisons; separate share date and analysis date, no invented roll-forward. Regression: integrity.test.ts.
3. Direct YTD conversion validates labels and ordering but not the actual fiscal calendar. Require contiguous expected YTD dates; EPS subtraction remains forbidden. Regression: integrity.test.ts.
4. Annual chart and historical comparator tie selection is order-dependent. Require unambiguous same-basis/scope periods and anchor history to the selected report.

## Modules and sequencing

A: explicit period compatibility, opening/comparable ambiguity guards, restatement metadata and fiscal-calendar tests.
B: valuation/report/publication/price/share dates, stale/future market checks, conservative corporate-action locks and date explanations.
C: quality report with field lineage, unverified/mock labels, missing/unit/source/cross-statement warnings. Never auto-balance or promote validated JSON to VERIFIED.
D: four-quarter TTM and FY+YTD−priorYTD, exact coverage and compatible bases, missing/ambiguous periods blocked, EPS withheld without sufficient share evidence.
E: three independent numerical fixtures with explicit arithmetic; no expected values generated by production functions.
F: stable-state disclosure, terminal concentration/investment warnings and growth/margin/CAPEX/WACC/g sensitivity; WACC remains supplied.
G: retain UI and add selectors, quality/source/date/explanation panels. Update E2E to verify blocked date comparisons rather than stale numeric upside.

## Regression risks and gates

- Legacy JSON lacks share/analysis dates: disclose/lock rather than infer dates. Date equality for retrospective DCF differs from trailing market-ratio availability after publication.
- Do not mix annual flows with Q4 flows; balance ambiguity needs explicit resolution even if both dates are valid. Restatements must not silently override older versions.
- TTM derived facts need multi-input lineage. Never sum end-of-period balance sheets or subtract EPS.
- Null per-share/market comparison results require UI formatting guards; equity value may remain available when share timing is unknown.
- No currency conversion without FX evidence. No financial-institution unlock.
- Test pure calculations and integrated UI with independent fixtures; run lint, typecheck, unit, build and Chrome E2E. Preserve unrelated QA screenshot changes. No Phase 3–5 start, production deploy or paid APIs.
