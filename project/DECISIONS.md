# Orchestrator decisions

- Isolated Node module; no changes to financial formulas or application UI. Uses existing Zod and Node built-in SQLite/HTTP/child_process. Node 24+ with node:sqlite required (tested with 25.2.1; SQLite still emits an experimental warning).
- SQLite in the worktree Git directory is the orchestration authority; JSON/Markdown files are readable exports carrying a revision. Exports are atomic individually, not a multi-file transaction. Regenerate from SQLite after interruption; never import an export as approval. Git remains authoritative for actual code/branch/commit/dirty status.
- One live manager lock per canonical worktree; lock expiry never steals a live PID. After a dead manager, unresolved work becomes UNKNOWN and requires owner reconciliation. PID reuse conservatively blocks recovery; no taskkill by stale PID.
- No background service installed. Restart starts stopped. Stop/Pause drain active work and prevent new dispatch; they do not promise to forcibly terminate a process tree.
- Default manual worker fallback. Optional native Codex exec adapter uses ChatGPT CLI authentication, explicit workspace-write sandbox, no approval bypass, no arbitrary command output execution. No real Codex generation or quota-recovery experiment was authorized by phase approval during implementation.
- Approval/acceptance is a local-owner dashboard action, bound to plan hash. Independent review evidence is required after external QA. This is not multi-user authentication or cryptographic proof of reviewer independence; the owner must actually inspect independent evidence.
- Trust boundary: trusted local owner and trusted repository/worker. Codex sandbox is supplied by Codex; this app is not a hostile-worker isolation platform. Same-account unrestricted programs can modify state/code. Post-run scope checking detects scope violations but cannot undo actions already performed. QA runs repository scripts with local user permissions. Use manual mode for untrusted workers/code; a future isolated worker identity/VM and separate QA environment are required before stronger autonomy claims.
- Quota status is only recognized from explicit supported structured error codes. Unrecognized CLI errors are UNKNOWN. Cooldown is a conservative minimum one hour, not a prediction of quota reset. Retry is operator-triggered and bounded; no polling of login/usage endpoints and no quota bypass.
- Existing third-party Codex Auto Resume is independent. Do not configure it to resume orchestrator worker sessions: two recovery owners would violate single-delivery assumptions. CLI adapter is experimental until this external interaction and process-tree lifecycle have been verified; manual mode is the supported local operating mode here.
